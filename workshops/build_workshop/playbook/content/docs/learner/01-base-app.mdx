## Starting point

You are on `build-workshop-v1` (cloned in module 00) — no checkout needed. Budget about **5 minutes**.
The workshop stack you started in module 00 should still be running.

Prerequisites: module 00 complete, the stack healthy, the front end reachable at
`http://localhost:8080/`.

## Why

You cannot improve what you have not seen. Before you touch ClickHouse Cloud, spend a
few minutes understanding the app's shape: what the two dashboards are for, how the front
end, back end, and databases fit together, and where the AI chat panel lives. This is the
only module with nothing to build, and that is deliberate.

## Goal

Be able to describe, in one sentence each, what the Ops dashboard is for, what the
Historical dashboard is for, and where the app's data will come from (there is none yet —
you seed ClickHouse Cloud in module 02 and stream live data in module 03).

## Step 1 — Open the Ops dashboard

### `frontend/`

Open `http://localhost:8080/`. This is the Ops dashboard: the cards, filters, and layout
for live operational metrics (recent trips, active zones, near-real-time aggregates). On
the workshop path there is no data behind it yet — the cards render empty because the app
talks only to ClickHouse Cloud, which you connect and seed in modules 02-03. You are here
to learn the structure, not to read numbers.

## Step 2 — Open the Historical dashboard

### `frontend/`

Open `http://localhost:8080/historical`. This dashboard is built for large-range
aggregations and drilldowns over historical trip data. Try the date-range and filter
controls to see how it is meant to work; the charts stay empty until module 02 seeds the
historical data into ClickHouse Cloud.

## Step 3 — Find the chat panel and trace the data flow

### `backend/`

Locate the AI chat panel in the UI (you wire it to a real model in module 07). Then look
at how the front end calls the FastAPI back end, and how the back end is wired to query
ClickHouse — the service it points at is your Cloud service, connected in module 02.

```text
React front end  ->  FastAPI back end  ->  ClickHouse Cloud (you connect it in module 02)
                                        ->  Postgres (operational source; CDC in module 03)
```

Ask your coding agent to summarize the analytics endpoints:

```text
Read the FastAPI backend and list each analytics endpoint, what it returns, and which
table it reads from.
```

## How to verify you are done

- You have opened both dashboards and seen the cards, filters, and layout render (the
  data is empty until modules 02-03 — that is expected).
- You can name where the app's data will come from (ClickHouse Cloud, seeded in module 02;
  live CDC in module 03).
- You know where the chat panel is, even though it is not wired to a model yet.

## Wrap-up

You have a mental model of the app: two dashboards, a FastAPI API, a source Postgres,
and a chat panel waiting to be connected. Every later module changes one part of this
picture.

## End state

You understand the running app. Continue to
[02 ClickHouse Cloud](/docs/learner/02-clickhouse-cloud) to give it a real analytics
warehouse.
