## Starting point

You are on `build-workshop-v1` — no checkout needed. Budget about **15 minutes**.

Prerequisites: telemetry flowing into ClickStack (module 05), your coding agent working
with MCP support (module 00).

## Why

Your agent is already good at writing SQL. Give it your observability data and the right
tools, and it can do SRE work: build a dashboard that surfaces the app's health and an
alert that fires when something goes wrong. This module wires the agent to ClickStack
and puts it to work.

## Goal

Your agent, connected to the ClickStack MCP, has saved an SRE dashboard and at least one
alert against your telemetry.

## Step 1 — Add the ClickStack MCP to your agent

First enable MCP on your service: in the console open the service, click
**Connect -> Connect with MCP**, and turn on the toggle. Then connect your coding agent
to the hosted ClickStack MCP endpoint (`https://mcp.clickhouse.cloud/clickstack`,
streamable HTTP with browser OAuth using your ClickHouse Cloud login). The endpoint
exposes the tools this lab uses: `clickstack_search`, `clickstack_timeseries`,
`clickstack_query_tile`, `clickstack_save_dashboard`, and `clickstack_save_alert`.

### your tool's MCP config

Add the server with your tool's command, then authorize in the browser:

```bash
# Claude Code
claude mcp add --transport http clickstack https://mcp.clickhouse.cloud/clickstack
#   authorize: run /mcp inside claude, or: claude mcp login clickstack

# Codex CLI
codex mcp add clickstack --url https://mcp.clickhouse.cloud/clickstack
codex mcp login clickstack
```

```jsonc
// Cursor — .cursor/mcp.json
{ "mcpServers": { "clickstack": { "url": "https://mcp.clickhouse.cloud/clickstack" } } }

// Windsurf — ~/.codeium/windsurf/mcp_config.json
{ "mcpServers": { "clickstack": { "serverUrl": "https://mcp.clickhouse.cloud/clickstack" } } }

// Windsurf fallback if native OAuth is flaky: the mcp-remote command form
{ "mcpServers": { "clickstack": { "command": "npx", "args": ["-y", "mcp-remote", "https://mcp.clickhouse.cloud/clickstack"] } } }
```

### auto-approve so the investigation is not interrupted

Allow the ClickStack tools to run without a prompt on every call:

- **Claude Code** — `.claude/settings.json`: `"permissions": { "allow": ["mcp__clickstack"] }`
- **Cursor** — `.cursor/permissions.json`: `"mcpAllowlist": ["clickstack:*"]`
- **Codex CLI** — `~/.codex/config.toml`, under `[mcp_servers.clickstack]`:
  `default_tools_approval_mode = "auto"`
- **Windsurf** — set auto-execution to Allowlist (or Turbo for the session) in settings.

<Callout>
  Your trial org has a single service, so no extra scoping is needed. Only on a
  multi-service org (or a loaner service) add an `x-service-id` header to the clickstack
  entry with the service UUID. TODO: the loaner service pool lands with the workshop
  infrastructure.
</Callout>

## Step 2 — Have the agent build an SRE dashboard

Prompt your agent to explore the telemetry with `clickstack_search` and then save a
dashboard covering request rate, error rate, and latency.

```text
Using the clickstack MCP, explore the app's traces and logs, then build and save an SRE
dashboard showing request rate, error rate, and p95 latency per service.
```

## Step 3 — Add an alert

Ask the agent to save an alert (via `clickstack_save_alert`) on the error-rate signal,
with a threshold it can justify from the baseline it just observed.

<Callout>
  There is no MCP tool to create a notification webhook. Pre-create the webhook in the
  HyperDX UI first; then the agent's saved alert can target it.
</Callout>

## How to verify you are done

- A saved SRE dashboard appears in HyperDX with the health signals populated.
- A saved alert exists with a sensible threshold.
- You can articulate what the dashboard would look like during an incident.

## Wrap-up

You now have an agent that can not only query telemetry but build durable observability
artifacts from it. That is exactly what you will lean on when something breaks.

## End state

An AI-built SRE dashboard and alert are in place. Continue to
