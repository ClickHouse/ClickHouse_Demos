Welcome. By the end of 25 minutes you'll have a local LibreChat instance talking to your own ClickHouse Cloud service via the remote MCP server, traced into Langfuse, with telco data ready to query through Claude.

Step 01aClickHouse Cloud

  1. Log in to console.clickhouse.cloud
  2. Create or pick a service — free Development tier works
  3. Connect → HTTPS → grab host and password
  4. Service UUID — read from the service page URL: console.clickhouse.cloud/services/<SERVICE_UUID>
  5. Organization UUID — open the org switcher in the top-left, or visit Organization → Settings; the URL will be /organizations/<ORG_UUID>/…
Save both UUIDs — they go directly into librechat.hybrid.yaml in Step 06, not into .env (LibreChat doesn't substitute env vars in serverInstructions).
Service UUID is in the service-page URL. Org UUID is NOT in the service URL — grab it from the org switcher dropdown or the Organization settings page.

Step 01bLangfuse Cloud

  1. Log in to cloud.langfuse.com (or us.cloud.langfuse.com)
  2. Create a project — e.g. telco-workshop
  3. Settings → API Keys → Create new API keys
  4. Save the public key (pk-lf-…) and secret key (sk-lf-…)
  5. Note the region's base URL
LANGFUSE_PUBLIC_KEY=pk-lf-...
LANGFUSE_SECRET_KEY=sk-lf-...
LANGFUSE_BASE_URL=https://cloud.langfuse.com    # or us.cloud.langfuse.com
Langfuse free tier covers ~50k observations/month — more than enough for a workshop. EU vs US region: pick whichever is closer.

Step 01cAnthropic API key

  1. Log in to console.anthropic.com
  2. Add ~$5 of credit (Settings → Billing) if new
  3. API Keys → Create Key
  4. Copy sk-ant-api03-… immediately — shown once
The key won't be visible again after you close the dialog. Save it before clicking away.
Checkpoint — 8 values captured. Move to Step 02.
Default presets use Claude Opus 4.6, Sonnet 4.6, and Haiku 3.5. A workshop session typically uses under $1 of credit per attendee.

What this does

  • Copies .env.hybrid.example → .env

Does not touch your cloud credentials — those go in next.

Your org/service UUIDs do not go here. They're pasted directly into the YAML in Step 06.
These are the only lines they need to edit. Everything else has working defaults.

Step 05Enable Remote MCP

  1. ClickHouse Cloud console → your service
  2. Connect in the left sidebar
  3. Toggle on Remote MCP Server
https://mcp.clickhouse.cloud/mcp
Endpoint is already wired into librechat.hybrid.yaml. OAuth gates access — LibreChat prompts you in the browser on first tool call.
The Remote MCP toggle is on the Connect page next to the HTTPS/Native tabs.

Step 06Pin UUIDs in YAML

LibreChat doesn't substitute ${VAR} inside serverInstructions, so the IDs go in the YAML directly.

Open librechat.hybrid.yaml (line ~54) and replace both UUIDs with your own:

serverInstructions: |
  TARGET (skip discovery; pass these IDs directly to every tool call):
  - organization_id: <YOUR-ORG-UUID>
  - service_id:      <YOUR-SERVICE-UUID>
  Do NOT call get_organizations or get_services_list ...
Without this, Claude burns 1–2 turns enumerating every org/service before each query.
Only manual file edit in the entire flow. LibreChat env-var substitution is only supported on apiKey/url/headers fields. Future iteration could templatize via sed.

Step 07Initialize schema

make init-schema

Spins up an ephemeral clickhouse-client container, connects to your Cloud service over HTTPS, and applies clickhouse/init.sql:

  • 4 tables: customers, call_detail_records, network_events, marketing_campaigns
  • 3 materialized views: customer_usage_summary, network_health_summary, campaign_performance
Expected: [OK] Schema initialized
If you see an SSL or auth error, double-check CLICKHOUSE_HOST and PASSWORD. The native TCP port 9440 is used; some corporate firewalls block it.

Step 08Generate data

make generate-data
Medium preset · default
10K Customers
7.8M Call records
300K Network events
100 Campaigns

Generation ~20 s · insert to Cloud ~30–60 s. Total under 2 minutes.

Smaller dataset? Set DATA_SIZE=small in .env (1K customers, finishes in seconds).
The data generator is vectorized numpy + column-oriented inserts. Memory peaks under 200 MB for medium. For 2xl (234M CDRs), 5-10 min total.

Step 09make start

make start

Brings up LibreChat, MongoDB, Meilisearch. Blocks until LibreChat's health check passes (~30 s first run), then auto-creates the workshop user.

[OK] Default user created: admin@telco.local / workshop123
Run docker ps — telco-librechat should show (healthy).
Order: generate-data is Step 08, start is Step 09. The data-gen container is a one-shot and stays exited after step 08 — that's fine.

Step 10Verify

make check-db

Expected row counts:

customers              10000
call_detail_records    ~7800000
network_events         300000
marketing_campaigns    100
All four tables populated — ready to chat.
Zero counts → data-generator didn't connect; re-check credentials. Dramatically wrong → ran generate-data twice without truncating; use `make clean-data` to truncate and re-run.

Step 11Open LibreChat & chat

  1. Browse to localhost:3080
  2. Log in: admin@telco.local / workshop123
  3. Default preset = Claude Opus 4.6, ClickHouse MCP tool already attached
  4. First message — try:
Show me the top 10 customers with the highest churn probability.
First tool call → OAuth prompt for ClickHouse Cloud. Approve once; token is cached for the session.
Watch the tool-call panel: Claude passes the pinned organization_id and service_id directly to run_select_query, skipping discovery.

Step 12Inspect traces in Langfuse

  1. Open cloud.langfuse.com → your project
  2. Traces sidebar — one trace per chat message
  3. Click any trace → drill into generations + tool calls

Per trace

  • Full system + user messages
  • Claude's tool calls and the SQL produced
  • MCP responses (raw row data)
  • Token counts & latency at every step
This is the LLMOps view your team would use in production — debugging, cost tracking, prompt iteration.
Traces appear within 5-10 seconds of the response. Show the cost-per-trace breakdown — Opus 4.6 is the most expensive; Sonnet 4.6 cuts cost ~5x.
